## Ce qui a bien fonctionne

- Progression incrementalement coherente entre UI, backend, migration, puis validation integration.
- Forte discipline de non-regression sur le mode manuel existant.
- Couverture tests renforcee (backend + UI + integration conditionnelle).
- Amelioration continue via code reviews adversariales avec corrections completes.
- Durcissement securite/fiabilite: anti-rejeu code OAuth, selection deterministe WABA/phone, reduction surface de reponse backend.

- Multiples points critiques detectes en revue (scopes Embedded Signup, robustesse loader SDK, execution test hors page cible).
- Risque de derive de version Graph/SDK identifie et necessite d'alignement explicite.
- Variabilite environnementale du test sandbox (prerequis env stricts) qui complique la reproductibilite hors contexte configure.
- Tension produit/technique entre rapidite de migration et maintien du fallback manuel.

## Enseignements cles

- Les garde-fous de scope par story ont evite les regressions transverses.
- Le choix "point d'entree backend unique" (`connectWhatsAppEmbedded`) simplifie maintenance et coherences.
- Le format CR avec severite explicite (HIGH/MEDIUM/LOW) accelere la priorisation et la correction.
- Les tests UI de contexte (chargement SDK uniquement page cible) ont apporte une protection concrete.
